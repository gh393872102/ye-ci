# 《夜祠》开发规范（交给 GPT-Astra）

本目录是给执行模型 **GPT-Astra** 的分阶段开发圣经，和 [GDD v0.2](../README.md) 配套使用。设计方案规定「做成什么样的游戏」，本目录规定「按什么顺序做、做到哪算过、每次该贴怎样的提示词」。

**在线阅读：** [开发规范专页](https://gh393872102.github.io/ye-ci/dev.html)（与设计方案同一站点，单独成页，便于交给 Astra 时只发一个地址）

**设计方案全文：** https://gh393872102.github.io/ye-ci/

请先读 [00. 给 Astra 的总说明与工作协议](00-给Astra的总说明与工作协议.md)，再按阶段打开对应文档。不要从中间阶段起做，也不要在未通过考核时进入下一阶段。

## 四个验收门槛（与 GDD 第 21 章对齐）

| 门槛 | 覆盖阶段 | 一句话 |
| --- | --- | --- |
| G0 规则能玩 | P0–P4 | 一块可平移的正门庭 + 二楼，守香与夺名都能用指定六人打完，暂停和决策指令可靠 |
| G1 一夜能成 | P5–P7 | 完整夜程图、三选一、至少三条流派能打出对应爽点 |
| G2 编制入场 | P8–P10 | 32+32 数据与立绘全部入表，图鉴可点，观祭可编排，关卡块与科仪齐 |
| G3 可上架 | P11–P12 | 例夜到无册夜、三条结局、性能、键鼠手柄、文本与音效达到 1.0 |

## 权威顺序

设计冲突以 [GDD v0.2](../docs/夜祠_游戏设计文档_v0.2（全文）.md) 为准。工程顺序、提示词、阶段考核以本目录为准。数字以 `tables/` 里的初稿为准，测试后只调数字，不改规则骨架。
